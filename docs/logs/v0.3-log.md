## Shipped

1. **Overpass hardening** (the only thing that hurt v0.2):
   `backend/data/overpass.py` — mirror failover chain
   (`overpass-api.de` → `overpass.kumi.systems`, env-overridable via
   `ATLASIS_OVERPASS_MIRRORS`), `/status` probe with short timeout,
   last-good-mirror memory, and client/server timeout decoupling
   (`(10, 170)` s client tuple; server-side `[timeout:180]` preserved —
   osmnx formats `requests_timeout` into the query string, so a scalar
   fast-fail would have capped server-side query time too).
2. **Combined forbidden query**: `FORBIDDEN_TAGS` list → single dict (osmnx
   unions per key; list values group under one key), five sequential
   requests → one. Per-layer try/except removed (all-or-nothing fetch);
   atomic `.part` + rename write; boundary default now fails fast with
   instructions instead of an opaque `FileNotFoundError` from `gpd.read_file`.
3. **`--skip-forbidden`** through `main.py` → `prepare.ensure_data` →
   `pipeline.run_pipeline` → `filters.apply_all_filters`, with a printed
   not-comparable warning; the fetch is deferred, not disabled forever.
4. **Heidelberg onboarding completed** (third country, DEU): combined
   forbidden fetch (682 zones), DEU density raster (3.0 MB), population
   cache (194 cells, ~153,618 people, within ~4% of the official figure).
5. **Kampala forbidden layer rebuilt** with the cemetery tag group
   (6,619 zones); full 5-min rerun reproduces the v0.2 headline exactly
   (+19,395, 98.7% → 99.8%).
6. **Fresh-city sanity check** (first-fetch overhead): Freiburg im Breisgau,
   a city never touched before, bootstrapped and run end to end in **92 s
   wall** (`time python -m backend.main --city freiburg --place
   "Freiburg im Breisgau, Germany" --threshold 300`) — geocode, roads,
   hospitals, one combined forbidden request, offline population crop
   (DEU raster already cached), scoring and baseline report included.
   Benchmark asked for < 10 min; v0.2 burned three ~10-minute windows on
   Heidelberg's forbidden step alone. Freiburg 5-min result: 66.4% →
   74.8%, +18,037 people (new lowest-baseline city; see analysis-v0.3).
7. **Joint MCLP selection** (the first methodological v0.3 layer):
   `backend/optimizers/mclp.py` — a candidate × population-node coverage
   matrix shared by a lazy-greedy solver (cost-benefit heap, >= (1 - 1/e)
   guarantee) and an exact PuLP/CBC MILP benchmark. The pipeline scores
   candidates FROM the matrix (marginal score = matrix row dot weights),
   so the independent ranking and joint selection cost one Dijkstra pass
   total, not two. CLI: `--num-sites k --mode greedy|exact|both`.
   Benchmarks hit (see analysis-v0.3 for the table): k = 1 reproduces
   known headline numbers exactly (Kolkata +42,711), exact solve 0.07-0.25 s
   on 300-candidate instances (< 1 min target), measured greedy gap 0.00%
   (Heidelberg, Kolkata) and 1.22% (Freiburg).
8. **E2SFCA accessibility index** (second scoring add-on):
   `backend/objectives/twosfca.py` — Gaussian decay over drive time
   (beta = tau_min^2 / ln(100), Luo & Qi calibration), facility-side
   Dijkstras on the reversed graph serving both steps, capacity pooling at
   shared nodes, optional per-facility `capacities`. Pipeline step [7b]
   computes baseline + optimized scenarios and exports per-cell scores to
   `data/processed/<city>/accessibility_{baseline,optimized}.gpkg`.
   Exact capacity identity (sum P_i A_i = total capacity) unit-tested;
   uniform-capacity caveat for the city-level scalar documented in the
   analysis (per-cell intensity surface is the informative part today).
9. **Shared synthetic-graph fixtures**: `tests/conftest.py` (line graph
   with 1 s hops + nearest_nodes stub) shared by the MCLP and 2SFCA tests.
10. **Uncertainty module** (third scoring add-on):
    `backend/objectives/uncertainty.py` — delete-1 jackknife (deterministic,
    per populated column) + seeded column/cell bootstraps over the four
    headline figures, all computed from the frozen coverage matrix (no extra
    Dijkstras). Explicitly documented as *sensitivity* intervals, not CIs
    (WorldPop is a modeled surface). CLI: `--uncertainty --n-boot N --seed S`.
    Verified on Freiburg: point estimates exact, interval shapes as
    documented.
11. **Kraków end-to-end** (fourth country, POL): first fresh city through the
    complete hardened fetch + tag-preserving facility cache + evidence-based
    curation. 8m54s wall bootstrap+run (server-bound: forbidden 2m36s, POL
    raster 1m41s); 5-min: 73.5% -> 78.9% (+40,751), joint k=5 91.7%, gap
    0.00%; population within ~7.9% of official. See analysis-v0.3.
12. **Hardened facility curation** (from the analysis-v0.3 review):
    `backend/gis/hospitals.py` — polygon footprint or mapped `beds > 0`
    overrides the (English-only) name blocklist in any language; generic
    `healthcare`/`building` tags are review aids, never overrides (rescuing
    on them reproducibly changed Mysuru's documented counts — first fix
    attempt caught and reverted); explicit per-city excludes stay absolute;
    tag-less caches print an honest "name-based only" note. Pinned by
    `tests/test_hospital_curation.py` (12 tests) and the **Kyoto test**
    `tests/test_hospital_curation_kyoto.py`: Japanese names built from
    unicode escapes (nothing hardcoded), an ASCII-only source guard on the
    curation module so no non-English name can ever live in the logic, and
    real-cache count pins (mysuru 85 / heidelberg 32 / freiburg 9 /
    krakow 26).
13. **Remaining cities' joint selections completed**:
    the case-study table's "—" cells filled. Guwahati, Patna, Kampala via
    `python -m backend.main --city <slug> --threshold 300 --num-sites 5
    --mode both` (all warm-cache, offline); Mysuru via the new
    `scripts/run_restricted_mysuru.py` (restricted 19-facility class; the
    pipeline has no facility-class flag). Headlines: Guwahati 85.4% →
    **99.8%** at k=5 (+70,082, the suite's largest joint gain, max drive
    time 11.5 → 5.3 min); Mysuru restricted 93.5% → **100.0%** at k=2
    (+44,691; exact MILP matches the objective with 3 — optimal sets not
    unique); Patna 98.6% → **99.6%**, greedy early-stops at k=2 (remainder
    = the 9,146 people with no road path); Kampala k=1 — the Rank-1 site
    (+19,395, reproduces the v0.2 headline exactly) already exhausts all
    reachable uncovered population. Every gap 0.00%. No code changed; the
    only new artifact is the Mysuru script. See the "remaining cities"
    section of analysis-v0.3.md.

## Noteworthy bugs found & fixed

| Bug | Fix |
|---|---|
| First draft of `overpass_call` raised `UnboundLocalError` when a probe returned unhealthy without raising (caught by `test_overpass_call_raises_when_all_mirrors_fail`) | try/except/else structure separating probe error from probe verdict |
| Scalar fast-fail `requests_timeout` would also shrink the server-side `[timeout:...]` budget (osmnx formats it into the query) | `(connect, read)` client tuple + hardcoded server timeout in `overpass_settings` |
| v0.2's per-layer try/except could write a forbidden cache missing layers (Kampala's missing cemetery group was exactly this failure mode) | all-or-nothing combined fetch; no partial cache |


## Constraints (current)

- Failover probes cost one HTTP GET per mirror before the first Overpass
  call of a session (subsequent calls reuse the last-good mirror).
- `--skip-forbidden` results are not comparable to filtered runs (warning
  printed); the flag exists for very unstable networks only.
- Overpass stability is still weather: hardening reduces blast radius
  (fast-fail + failover + one request instead of five), it does not make
  the public instances reliable.
