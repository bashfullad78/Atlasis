## Shipped

1. **Data provenance (Part 1).** `meta.json` becomes the
   provenance source of truth: `load_meta`/`persist_meta`
   (`backend/config.py`) merge resolved facts without
   clobbering; fetch stamps flow into every result payload as
   `data_stamps` + `data_as_of` and are shown in the UI footer,
   so a stale cache is visible at a glance. Pinned by
   `tests/test_provenance_stamps.py` + `tests/test_meta_persistence.py`.
2. **Async Jobs API (Part 2).** `backend/api/app.py` +
   `backend/api/runner.py`: `POST /api/jobs` enqueues (single
   worker thread, `QUEUE_CAP = 1`, per-IP soft window rate
   limit), `GET /api/jobs/{id}` returns poller-safe snapshots
   with live stage labels and **monotonic** `elapsed_s`
   (wall-clock went negative mid-run under container NTP
   jumps); failure is job state, not an HTTP error; the result
   payload (including reverse-Dijkstra isochrone layers) is
   built server-side. `web/` is mounted at `/` with `/api`
   routes matching first. Offline tests drive the pipeline
   through `_RUN_PIPELINE`/loader indirections — zero network,
   zero real city dirs.
3. **Interactive demo map (Part 3).** `web/index.html` +
   `web/app.js`: dark OSM/FOSSGIS-faithful Leaflet UI, form →
   running (stage + progress bar) → result/failed views,
   before/after coverage layers (baseline vs joint), server
   isochrone GeoJSON, ranked site list with gains, provenance
   stamps, mobile layout, `prefers-reduced-motion` respected.
   Browser-verified across idle/running/result/failed/mobile;
   four first-pass flaws closed (Esri basemap caps zoom 16,
   baseline layerGroup halo artifact, mobile toggle direction,
   full timestamps overflowed).
4. **240 s acquisition fallback.** `_run_job`: an acquisition
   `ConnectionError`/`TimeoutError`/`OSError` past the 240 s
   gate re-acquires with `skip_forbidden=True` and marks the
   job `comparable: False` (stage label exposed to pollers)
   instead of failing. Live-verified degraded completion:
   heidelberg job `603c5fa821e9` — 365 s gate, `done` in
   370 s, 80.51% → 93.19% honestly flagged NOT comparable.
5. **Acquisition resilience (live-fire).** `overpass_call`
   trusts the last-good mirror **without** a status probe
   (the probe traffic itself gets throttled — a fresh process
   could be blocked at `/status` while `/interpreter` served),
   `STATUS_PROBE_TIMEOUT_S = (5, 60)` after two same-day
   raises. Proven across five live fetches in three days:
   freiburg 5/5 (10-26, one kumi timeout → 40 s retry),
   heidelberg 5/5 (10-28, forbidden landed first try),
   guwahati 5/5 in a single shot (10-28), krakow 4/5
   (forbidden pending), kampala 3/5 (hospitals + forbidden
   pending; roads landed from an aborted attempt thanks to
   atomic part-file writes).
6. **External drive-time validation** (roadmap #2).
   `scripts/validate_drive_times.py`: 50 seeded OD node pairs
   per city, modeled edge time (`length / posted maxspeed`,
   the exact coverage-matrix model) vs the public OSRM demo
   router, 1 s/pair pacing, per-pair JSON reports in
   `docs/analyses/validate-<slug>.json`. Four cities
   (2026-10-28 wave after freiburg on 10-22): freiburg
   MAE 175.1 s (24.5%), krakow 199.8 s (24.2%) — both **every
   pair positive**, error compounding with trip length;
   guwahati bias +15.9 s with 29/21 sign split; kampala bias
   **−40.2 s** (model slower than OSRM, sign flipping with
   trip length). The calibration factor is therefore a
   tag-rich-only finding; tag-sparse cities trade bias for
   variance. Closes README limitation #2 with a split verdict;
   `docs/analyses/validation-v0.4.md`.
7. **Bed capacity wiring** (roadmap #3). OSM `beds > 0` →
   per-facility capacity column with uniform-1.0 fallback
   (absent/0/NaN/missing column → exactly the old
   presence-only semantics); pipeline feeds `capacities=` into
   both 2SFCA scenarios and prints "Bed capacity modeled: N/M".
   Pinned by `tests/test_beds.py`; live on heidelberg (1/32).
8. **Suite + CI hardening.** Suite grew **97 → 137 tests**
   (Jobs API lifecycle/queue/rate-limit/failure, provenance,
   meta persistence, beds, bootstrap prepare) — all offline.
   CI dependency audit found a fresh-install breaker: starlette
   1.6's `TestClient` imports `httpx2` at module load and
   **nothing in `requirements.txt` pulled it** (it was
   hand-installed in the dev venv) — every API test would fail
   at import on CI. Pinned `httpx2==2.16.0` + `httpcore2==2.16.0`;
   full fresh resolution verified with `pip install --dry-run`.
   Also: krakow's real-cache count pin moved 26 → 27 after the
   live re-fetch (benign OSM drift — dedup still drops 1 of 28
   raw features; curation semantics unchanged).

## Constraints (current)

- **One job at a time** by design: single worker thread, queue
  cap 1, per-IP soft window rate limit (503/429 surfaced as
  job/HTTP state). Any hosted deploy keeps this shape.
- **240 s fallback results are NOT comparable** (forbidden
  filter off until `forbidden.gpkg` exists) — flagged in the
  payload and the UI, never silently merged with filtered runs.
- **Isochrone payloads are large** (tens of thousands of SVG
  paths / MBs of GeoJSON on real cities); trimming is deferred
  as a hosted-deploy perf item, not done in v0.4.
- **Esri basemap tiles cap at zoom 16** (provider limit).
- **Real-cache pins cannot be checked by CI** — `data/raw` is
  gitignored, so the four count pins skip on a fresh checkout
  and only run where caches exist.
- **Overpass remains weather.** Failover + retry + one
  combined query shrink the blast radius; they do not make the
  public instances reliable. Windows on this box open for
  minutes at a time, randomly; `/status` probes gate nothing
  reliably — fire `ensure_data` and let its internal failover
  catch the window.
- **Validation coverage is 4 cities × 50 pairs, one router**
  (OSRM demo, paced); no Valhalla cross-check, and the demo
  server's courtesy limits throughput.
- **Wall-clock timings on the dev box are meaningless** (2
  CPUs shared with the editor/agent/browser; `pressure/cpu`
  ~33% at idle) — correctness is unaffected, all runs produce
  identical outputs.

## Standing limitations (not code-fixable — do not game-plan)

- **WorldPop 1 km modeled estimates** and the centroid
  resolution (the `0.0 min` artifact). Better resolution means
  100 m count rasters = full-country multi-GB downloads;
  rejected in the README by design.
- **OSM hospital completeness varies per city.** Retained
  counts are not a census; only per-city review (a process),
  never code.
- **Real-time traffic / congestion / emergency routing.** No
  free, reusable, realtime traffic source exists for this use
  case.
- **Parcel-level feasibility** (ownership, zoning, cost) —
  private data, out of open-data reach.
- **Public-instance capacity/payload rejections** (the 406/502/413
  fetch weather): the shared Overpass endpoints shed load globally —
  "all query workers busy" 502s, response-size 413s, mirror probe
  timeouts — against every caller, not per-egress bans (no recorded
  block message; sustained per-IP concurrency limits can still bite a
  shared egress). Fixed operationally if at all: pacing, chunked
  queries (`scripts/fetch_forbidden_chunked.py` solves the 413 for
  city-sized ones), pre-seeded caches, or a different network.
